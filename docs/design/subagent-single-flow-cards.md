# Pi 子代理独立单卡试用

## 范围与隔离

- 开发分支：`feat/subagent-single-flow-cards`；工作区：`/home/pan/work/tlive-card-subagents`；基线：`6f8ab60`（300 estimated Token 思考尾部试用版）。
- 本次接入的是 Pi 中字面名称为 `subagent` 的工具。单任务、并行 `tasks`、串行 `chain`、`resume` 使用各自稳定槽位。不是对所有提供商的 Agent/Task 工具作通用承诺。
- 仅飞书创建独立子卡；其他渠道保留原展示。主代理仍使用已有无损续卡规则，子卡的压缩不能影响主卡或模型工具结果。
- 不修改共享 Pi 扩展、原工作区、默认 CLI 或 systemd，不安装依赖、不推远端。当前正在试用的 bridge/client 未切换。

## 事件与身份

- `integrations/pi-subagent/` 是现有用户扩展的隔离副本。增加 `details.results[].flow = { version: 1, status, timeline }`，实时捕获文本/思考 delta 和工具开始、更新、结束；最终 message 不重复流式片段。
- `PiAdapter` 保留原工具事件和结果，额外生成经 schema 校验的 `subagent_snapshot`；远端协议与引擎转发该快照。旧版 `messages` 有兼容解析，但没有实时事件的旧扩展无法提供逐段思考。
- 卡片身份使用本地父 turn nonce、父工具调用 ID、子任务槽位；不按代理名称共享状态。同名并行任务、不同父调用和同名工具 ID 互不串卡。
- 工具 partial 中 `exitCode = 0` 不代表已完成。链式任务失败后尚未启动的槽位标中断，父结束后仍运行的子槽也标中断。
- 展示可以在主卡只保留委派状态；原始完整工具结果仍由模型/引擎消费，不在模型上下文中替换成界面摘要。

## 子卡规则

- 每个子任务只有一张进度卡：开始时立即创建，后续和最终状态始终修改该卡。点击思考/编辑详情仍使用原有独立、可关闭的详情机制，不属于自动续卡。
- 正常展示复用主卡的工具分类、50 estimated Token 分组和整卡共享 300 estimated Token 思考尾部预算、脱敏与详情权限。
- 每子流最多一个在途请求和一个最新待刷快照。刷新从请求开始计时，目标 400ms，慢网络合并旧快照，各子流独立推进。限流执行退避；不承诺手机端到端 400ms，也没有用 mock 验证应用级真实限流。
- 容量检查使用最终 UTF-8 卡片 JSON、请求转义、元素和表格预算。超过预算从最早内容开始：删除思考及其按钮；工具移除参数/结果/按钮，留下名称与失败/中断状态；文本截短保留后缀并显式标注。
- 工具名称仍过多时合并成有序列表，再极端压缩较早记录为计数/省略提示。超长 Markdown 可降为转义字面文本，避免半个围栏或表格造成格式破坏。
- 平台拒绝容量时降低预算，仍在同一物理消息中压缩重试，不调用普通续页规划。最小合法卡片也放不下时明确报错，不拆卡。
- 首次发送响应不确定时，保留原 UUID 和原请求重放确认，再更新最新快照；不会以编辑失败为由重新发送一张子卡。已结束状态不会因晚到 running 快照倒退。
- 父终态发送前等待子卡最终 flush；子卡最终展示失败会在主卡注明，不伪装为子代理执行失败或修改实际模型结果。

与上次只切 bridge 不同，这次要同时运行新版 bridge 和新版 client，才能获得新事件并加载隔离副本。切换必须另获确认，保留原进程参数/环境与回退工作区；先检查运行中任务，不能无提示终止活跃子代理。重启 bridge 会清空旧卡的内存详情缓存。
