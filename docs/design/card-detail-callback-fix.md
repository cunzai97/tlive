## 协议缺陷与复现

用户在话题卡片点击“查看新增内容”时收到“无权操作此详情，或卡片的聊天、话题、来源消息不匹配”。旧运行日志只有收到回调的记录，没有原始回调载荷，不能声称已读到那次点击的全部字段。

官方 `card.action.trigger` 回调结构说明 `context.open_chat_id` 与 `context.open_message_id`，不保证提供 `context.thread_id`：
https://open.feishu.cn/document/feishu-cards/card-callback-communication

旧代码对回调 `message.threadId` 与快照绑定话题作严格相等检查。话题快照有 ID，但标准回调没有此字段时，即使用户、聊天和来源卡均正确也会被拒绝。原测试全部人为填写话题字段，且误将缺失字段当作越权用例，未覆盖官方结构。

新增单元与 adapter/SDK 边界集成用例先在原代码执行，2 项因合法打开返回 error 而失败；修复后全部通过。这确认存在可复现的协议兼容缺陷，但真实客户端最终验收仍须重新试用。

## 修复与安全不变量

- 仅当回调明确提供话题字段时要求它与已绑定话题一致；明确冲突仍拒绝。
- 打开必须命中发送阶段已绑定的精确来源卡消息 ID；翻页/关闭必须命中本次详情卡精确消息 ID。
- 授权用户、快照所有者、聊天、通道、有效期等校验不变；不接受只知道快照 ID 的跨消息操作。
- 消息 ID 已在服务端绑定所属话题；缺失回调话题字段不等于解除话题隔离。
- 回复目的地始终来自已绑定快照路由，而非回调传入数据。无话题字段时仍向原话题回复，不回落到普通聊天。
- 不读取最新文件，不重新执行工具，不将详情回调传给模型。
