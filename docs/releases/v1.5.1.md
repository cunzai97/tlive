# v1.5.1

本版本把计划类工具（todo / plan / tasks）从通用工具流里分出来，改为会话级常驻的计划块。

## 主要变化

- 计划类调用按 JSON 结构识别，不再按工具名判定：`todos` / `tasks` / `plan` / `steps` / `items` / `checklist` / `subtasks` 等字段下的条目，每项同时具备状态与文本才算计划；任一条目不合规即整批判否，绝不渲染半截列表。
- Claude 的 `TodoWrite` 不再被客户端与服务端两处名字黑名单吞掉，计划块在该 provider 上首次可用；pi 与 Codex 行为不变。
- 卡片时间轴只保留"用了这个工具"一行，原始入参 JSON 与重复的 `完整结果` 折叠面板不再出现。
- 卡片底部新增常驻"工作进度"折叠块，随每次计划调用更新，且每张新卡都携带；更新只作用于最新那张卡。子代理卡不带计划块。
- 计划状态扩为五态：未开始、进行中、完成、取消、阻塞。`blocked` 不再折进 `pending`，取消与阻塞都不会被看成已完成。
- 计划板的所有权键改为复合 scope（渠道、chatId、userId、thread、scope、会话代次），缺少 scope 时拒绝存储，避免不相关会话共用一份计划；`/new` 轮换会话代次即自然失效，另有 1 小时 TTL 与容量上限。
- 空列表表示显式清除该会话的计划，与"未识别到计划"区分开。
- Codex 的计划条目支持 `step` 文本字段与 `inProgress` 驼峰状态。

## 使用说明与保留行为

- 计划块默认展开，可点击折叠；折叠状态能否在 400ms 快照刷新后保留**未经真实客户端验收**。
- Codex SDK 路径的 `emitTodoUpdate` 仍只读 `completed` 布尔，进行中的步骤会显示为未开始；app-server 路径不受影响。本版本未改动该 provider 侧行为。
- 计划识别只看结构，因此任何恰好携带"状态 + 文本"列表的工具入参都会进计划块。单对象任务工具（如 `TaskCreate` 的 `{subject, description, status}`）、无状态的文件列表、非白名单字段名的数组都不会命中。
- 计划板为内存状态，桥接重启后旧卡不再携带计划。

本次发布不合入 main，不推远端。
