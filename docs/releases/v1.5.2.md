# v1.5.2

本版本在 v1.5.1 的会话计划板之上补齐"这一轮正在发生什么"：思考过程改用原生代码块，write 还在生成就先露出内容，每个工具行标出自己那次调用的 token 花销，卡片刷新从 400ms 放慢到 1s。

## 主要变化

- 思考预览渲染为飞书原生代码块，随流增长的正文只保留最近约 300 token（约 1.2 KB 上界），完整思考仍在点击后展开。围栏是自适应的，正文里的反引号不会截断代码块；`#` 开头的行在代码块内不会被当成标题降级。
- `write` 的入参还在流式生成时，卡片底部那块"只在运行中存在"的区域就输出 `📝 正在写入 <路径> · 已生成 N 行 / M 字符`，并附一段最近约 300 token 的内容尾窗。write 一结束，整块消失，退回原有的"标题 + 查看新增内容按钮"形态。数据来自模型流的修复式解析快照，每帧覆盖、不累加，因此中断与失败都不留残块。
- 工具行标题去掉分类词（运行工具 / 探索工具 / 执行工具），换成这次调用的成本：`✅ 完成 · bash ↓3.2k ↑326 64k 80%`，依次是非缓存输入、输出、当前上下文、占上下文窗口的比例。折叠成组的工具显示组内合计，而不是每条重复一遍。
- 用量按"模型回合"记账：provider 只对 assistant 回合报 usage，从不按工具报，所以同一回合的并行调用共享同一份数字，渲染层按回合号去重；上下文取最大值而不是求和，因为上下文是累积量。`↓` 为 `input + cacheWrite`，与卡片页脚"输入(未缓存)"同源，`cacheRead` 不计。
- 卡片整卡 PATCH 的节流从 400ms 改为 1s。渲染节流、发送节奏与子代理卡共用一个常量，长回答下请求密度降到原来的 40%。
- 传输层没有新增事件种类、`REMOTE_PROTOCOL_VERSION` 仍为 1：回合用量作为 `tool_start` 的可选嵌套字段搭车，写进度作为 `tool_progress` 的可选字段搭车。schema 非 strict，旧桥接收到未知键会剥掉并照常工作，旧客户端不发就等于没有这两个功能。

## 使用说明与保留行为

- 写进度与 token 用量都只有 pi provider 有。`edit` / `replace` 与其他 agent（claude、codex）没有可用的入参增量通道，因此没有生成中预览；它们的工具行不带数字。
- 生成期间只能看到最近约 300 token 的内容，全文要点完成后的"查看新增内容"按钮 —— 那是 v1.5.1 之前就有的能力。
- 被中止或报错的模型回合不产生 usage，该回合的工具行会沿用上一个完整回合的数字，因此中断时的用量可能偏低。
- 内容尾窗是往卡片末尾追加一个元素，最坏约 +1.2 KB。若卡片本来就被顶到字节阈值边缘，write 期间可能被推成两页，write 结束后元素消失、尾页按现有分页逻辑撤回 —— 会看到一次尾卡出现又撤回，不是新 bug。
- 写进度依赖进程内 `createAgentSession` 保留的 partial 消息。若将来切到剥掉 partial 的 json-event RPC 模式，这两个功能会静默失效。
- 刷新改 1s 后，思考与生成的逐字更新观感会变慢，这是为消除卡顿做的刻意取舍。v1.5.1 里"折叠状态能否在快照刷新后保留"仍未经真实客户端验收，且当时的观察基于 400ms 节奏。
- 本次发布不合入 main，只发 `release/1.5.2` 分支与 `v1.5.2` 标签（与 v1.5.1 一致）。改动包含 `src/client/**`，所以桥接与 local client 必须一起替换才有效果，只换桥会没有写进度和用量数字。
